# Feature Specification: Shared Story Context for Episode Images

**Feature Branch**: `004-story-context`

**Created**: 2026-11-16

**Status**: Draft

**Input**: User description: "Give every image in an episode shared story context so the panels tell one connected story from first to last. Add a StoryContext type to EpisodePackage containing characters and their appearance, setting, era, lighting and palette, props, and art style. Generate StoryContext with an LLM from the episode brief, as a new step that runs before the script is built. Keep StoryContext generation in its own function so a user review/edit step can be added later. Prepend the story context to every image prompt (scenes and thumbnail). If the LLM call fails, fail clearly with an error; do not silently fall back to a generic context. Do not change the image provider or the model switching logic."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Every episode has a shared story context (Priority: P1)

As a creator, when I submit a location, era, and atmosphere, the episode package includes a StoryContext (characters and their appearance, setting, era, lighting and palette, props, art style) generated by an LLM from my brief, before the script is built.

**Why this priority**: Without a shared context there is nothing for the images to stay consistent with.

**Independent Test**: Submit a valid brief with `OPENAI_API_KEY` configured and confirm the returned EpisodePackage contains a complete StoryContext.

**Acceptance Scenarios**:

1. **Given** a valid brief and a working LLM, **When** generation is requested, **Then** the EpisodePackage contains a StoryContext with at least one character (name + appearance), setting, era, lighting and palette, at least one prop, and art style.
2. **Given** a valid brief, **When** generation runs, **Then** the StoryContext step completes before the script and prompts are built.

---

### User Story 2 - Every image prompt carries the story context (Priority: P1)

As a creator, every image generated for an episode (each scene and the thumbnail) receives the same story context, so characters, setting, lighting, props, and style stay consistent from the first panel to the last.

**Why this priority**: This is the continuity outcome the feature exists for.

**Independent Test**: Generate assets for a package and confirm every asset record's `promptText` starts with the same story context block followed by that asset's own prompt.

**Acceptance Scenarios**:

1. **Given** an EpisodePackage with a StoryContext, **When** image assets are generated, **Then** the story context block is prepended to every scene prompt and to the thumbnail prompt.
2. **Given** an image generation request whose package has no valid StoryContext, **When** it is submitted, **Then** it is rejected with a validation error.

---

### User Story 3 - LLM failures are explicit (Priority: P2)

As an operator, if the story context cannot be generated, I see a clear error and no package is produced.

**Why this priority**: A silent generic fallback would defeat continuity without anyone noticing.

**Independent Test**: Remove `OPENAI_API_KEY` or force the LLM call to fail and confirm the episode request returns a distinct `STORY_CONTEXT_FAILED` error with no package.

**Acceptance Scenarios**:

1. **Given** `OPENAI_API_KEY` is missing, **When** generation is requested, **Then** the request fails with `STORY_CONTEXT_FAILED` and a message naming the missing key.
2. **Given** the LLM call errors or returns malformed or incomplete output, **When** generation is requested, **Then** the request fails with `STORY_CONTEXT_FAILED` and no generic context is substituted.

### Edge Cases

- The LLM returns valid JSON that is missing fields, has empty strings, or has an empty characters/props list.
- The LLM returns non-JSON text or an empty response.
- The LLM call times out, is rate limited, or the key is rejected.
- A brief is missing location, era, or atmosphere (existing needs-input behavior applies; no LLM call is made).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `EpisodePackage` MUST include a `storyContext: StoryContext` field with `characters` (name + appearance), `setting`, `era`, `lightingAndPalette`, `props`, and `artStyle`.
- **FR-002**: StoryContext MUST be generated by an LLM from the validated EpisodeBrief, in a step that runs before the script is built.
- **FR-003**: StoryContext generation MUST live in its own function (`generateStoryContext`) that takes the brief and an LLM client, so a review/edit step can later sit between it and package building.
- **FR-004**: The story context MUST be prepended to every image prompt sent for generation: each scene prompt and the thumbnail prompt.
- **FR-005**: If the LLM call fails or returns output that fails runtime validation, the system MUST return a clear `STORY_CONTEXT_FAILED` error and MUST NOT substitute a default or generic context.
- **FR-006**: The image provider (`lib/assets/provider-adapter.ts`) and its model switching logic MUST NOT change.
- **FR-007**: Episode generation MUST run on the server so the OpenAI key never reaches the browser.
- **FR-008**: The LLM model MUST default to `gpt-4.1-mini` and be overridable via `OPENAI_STORY_MODEL`.

### Key Entities

- **StoryContext**: Shared visual facts for one episode: characters (name, appearance), setting, era, lighting and palette, props, art style.
- **StoryContextLLM**: Minimal client interface (`completeStoryContext(brief) => Promise<unknown>`) used by `generateStoryContext`; the OpenAI implementation is one adapter.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of generated EpisodePackages contain a StoryContext that passes runtime validation.
- **SC-002**: 100% of image generation calls for a package receive a prompt that begins with that package's story context block.
- **SC-003**: 100% of LLM failures (missing key, API error, malformed output) produce `STORY_CONTEXT_FAILED`; zero packages are produced with a substituted context.
- **SC-004**: Unit tests cover StoryContext generation and prompt building; lint, build, and tests pass.

## Assumptions

- The same brief no longer guarantees the same EpisodePackage, because the StoryContext comes from an LLM. The Phase 1 spec is updated accordingly.
- `OPENAI_API_KEY` is the only credential needed for the LLM call.
- A user review/edit step for StoryContext is out of scope for this feature.
- Scene prompt and script templates are otherwise unchanged in this feature.
