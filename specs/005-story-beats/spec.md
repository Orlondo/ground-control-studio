# Feature Specification: Emotional Story Beats for Episode Panels

**Feature Branch**: `005-story-beats`

**Created**: 2026-11-16

**Status**: Draft

**Input**: User description: "Each panel visually conveys a specific emotion, concept or thought from its story beat, using composition, lighting, framing and character expression, not text. The brief sets the overall tone. The LLM breaks the story into beats and gives each beat its own emotion within that tone, so the episode has an emotional arc. Use one beat list as the single source for both the script and the image prompts."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - The episode is told as a list of emotional beats (Priority: P1)

As a creator, when I submit a brief, the episode package includes 4–6 story beats generated by an LLM after the StoryContext. Each beat has a one-sentence summary, an emotion within the brief's tone (the atmosphere field), a visible action, and composition, framing, lighting and character-expression directions.

**Independent Test**: Generate an episode with a fake LLM and confirm `package.beats` holds 4–6 complete beats whose adjacent emotions differ.

**Acceptance Scenarios**:

1. **Given** a valid brief and working LLM, **When** generation runs, **Then** the package contains 4–6 beats, each with non-empty summary, emotion, action, composition, framing, lighting and expression.
2. **Given** generated beats, **When** they are checked, **Then** no two adjacent beats share an emotion (an emotion may recur later, e.g. calm at start and end).
3. **Given** generated beats, **When** a separate tone-fit judge reviews them, **Then** every emotion fits the brief's tone.

### User Story 2 - One beat list drives the script and every panel (Priority: P1)

As a creator, the script and the scene prompts are both built from the same beats, so the images follow the story from beat to beat.

**Acceptance Scenarios**:

1. **Given** beats, **When** the package is built, **Then** the script has one line per beat (its summary) in beat order.
2. **Given** beats, **When** the package is built, **Then** there is exactly one scene prompt per beat, and each includes "Panel n of N", the beat's emotion and action, and its composition, framing, lighting and expression.
3. **Given** any image prompt (scene or thumbnail), **When** it is sent to the image model, **Then** it carries the StoryContext and an instruction forbidding text, captions, speech bubbles, signage and lettering.

### User Story 3 - Invalid beats fail clearly (Priority: P1)

**Acceptance Scenarios**:

1. **Given** the first beats response has an empty beat, a missing emotion, the wrong beat count, repeated adjacent emotions, or an emotion the judge says clashes with the tone, **When** generation runs, **Then** beat generation is retried once, with the issues passed back to the LLM.
2. **Given** the retry is also invalid, **When** generation runs, **Then** the request fails with `502 STORY_BEATS_FAILED` and a message listing the issues; no package is produced and no fallback beats are used.
3. **Given** the LLM call itself errors (auth, network, rate limit), **When** generation runs, **Then** it fails immediately with `STORY_BEATS_FAILED` without retrying.

### Edge Cases

- Judge output malformed or missing a verdict for a beat: counts as an invalid attempt.
- Human review and editing of beats is out of scope; beat generation stays in its own function so it can be added later.

## Requirements *(mandatory)*

- **FR-001**: `EpisodePackage` MUST include `beats: StoryBeat[]` (`order`, `summary`, `emotion`, `action`, `composition`, `framing`, `lighting`, `expression`).
- **FR-002**: Beats MUST be generated by `generateStoryBeats(brief, storyContext, llm)` in `lib/episode/story-beats.ts`, after StoryContext and before the script is built, using `gpt-4.1-mini` (overridable via `OPENAI_STORY_MODEL`) with strict JSON schema output.
- **FR-003**: Tone fit MUST be judged by a separate `gpt-4.1-mini` call that returns a verdict per beat.
- **FR-004**: Beats MUST be 4–6 in number, complete, and adjacent emotions MUST differ (case-insensitive).
- **FR-005**: Invalid beats or tone clashes MUST trigger exactly one retry; a second failure MUST raise `StoryBeatsGenerationError` → `502 STORY_BEATS_FAILED`. LLM transport errors MUST NOT be retried. No silent fallbacks.
- **FR-006**: The script and scene prompts MUST both be built from the beat list; each scene prompt MUST include its beat's emotion and action.
- **FR-007**: Every image prompt MUST forbid text, captions, speech bubbles, signage and lettering.
- **FR-008**: The image model (`gpt-image-2`), image provider, and text model default (`gpt-4.1-mini`) MUST NOT change.

## Success Criteria *(mandatory)*

- **SC-001**: Looking at the generated images alone, a viewer can follow what happens from beat to beat (verified manually by the owner with a real key).
- **SC-002**: Every beat has its own emotion and emotions change between adjacent beats.
- **SC-003**: Unit tests prove each scene prompt includes its beat's emotion and action, and cover beat validation, tone-clash handling, retry and error paths.
- **SC-004**: All pre-existing tests still pass (updated only where the package now requires beats).

## Assumptions

- The brief's `atmosphere` field is the episode's overall tone.
- Beat count is chosen by the LLM within 4–6; there is no fixed three-scene layout any more.
